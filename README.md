# Бэкенд каталога бенчмарков

Каталог помогает подобрать испытания для языковой модели, понять, что они проверяют, и посмотреть уже сохранённые результаты. Можно просматривать карточки, пользоваться фильтрами, запросить рекомендацию и предложить новый Test на модерацию.

**Каталог не запускает испытания и не обучает модели.** Он хранит своё представление испытаний, справочники, метрики, результаты, пользователей и пользовательские сценарии. Описания самих Benchmark, Test и DatasetSubsample принадлежат отдельному **Benchmark Service**.

Документация описывает текущую реализацию после разделения сервисов. Проверена по коду 16 сентября 2026 года. Run, полноценные версии Test и ModelVersion — не существующие функции этой версии.

## Главное различие в названиях

| Название | Простое объяснение | Пример |
| --- | --- | --- |
| Benchmark | Группа испытаний | GPQA, MERA Text, BFCL |
| Test / BenchmarkTest | Конкретное испытание внутри группы; обычно ему соответствует карточка в UI | GPQA Diamond, ruMMLU |
| DatasetSubsample | Описанная часть данных одного Test; используется для показа его состава | Раздел Test с примерами определённого типа |
| Metric / MetricDefinition | Что именно измеряем | Exact Match, pass@1 |
| MetricResult | Уже полученное число для одного Test, одной модели и одной Metric | Доля точных ответов конкретной модели |
| CatalogEntry | Решение каталога о публикации Test и сведения о модерации | Заявка автора в состоянии `validation` |

В интерфейсе слово «бенчмарк» иногда означает карточку Test. В коде `Benchmark` — её родительская группа. Например, исходный набор содержит **10 Benchmark и 40 Test**, а UI показывает «40 бенчмарков».

## Как это работает в целом

```text
Пользователь → фронтенд → API каталога → БД каталога
                              │
                              └─ изменение Benchmark/Test
                                 → Outbox → Kafka → Benchmark Service
                                                       │
                                                       ├─ своя БД
                                                       └─ Outbox → Kafka
                                                                    │
                                         копия для чтения в каталоге ←┘
```

Открытие карточки не требует HTTP-вызова Benchmark Service: каталог читает свою копию, полученную из Kafka. При изменении он возвращает номер операции; интерфейс ждёт подтверждения, а не считает сам факт отправки успешным сохранением.

Подробная схема с внешними модельными сервисами и объяснением очередей — в [архитектуре](docs/architecture.md).

## Быстрые ориентиры для разработчика

| Что ищете | Где смотреть |
| --- | --- |
| Общие настройки HTTP, `/api`, проверка входных данных | `src/configure-application.ts`, `src/main.ts` |
| Чтение карточек, фильтры и группировка каталога | `src/catalog/projection/`, `src/catalog/catalog-view/` |
| Запись в Benchmark Service через Kafka | `src/benchmark-service/integration/` |
| Статус асинхронной записи | `benchmark-command-status.service.ts` в том же модуле |
| Модерация и заявки автора | `src/catalog/catalog-entry/` |
| Таксономия и справочники | `src/catalog/settings/` |
| Метрики, модели и результаты | `src/metrics/` |
| Поиск по смыслу и поисковый индекс | `src/catalog/search/` |
| Подбор и выбор рекомендаций | `src/recommendations/` |
| Диалоги и соединение с интервьюером | `src/conversations/` |
| Предложенные гипотезы | `src/hypotheses/` |
| Внешнее API и ключи доступа | `src/external-api/`, `src/vault/` |
| Таблицы каталога | `prisma/models/` |
| Тесты с настоящей БД | `test/` |

Техническая основа: TypeScript, NestJS, PostgreSQL с pgvector, Prisma, Kafka и Socket.IO. Каждый из этих компонентов объяснён в документации, знания ML для чтения не требуются.

| Swagger Benchmark Service | `http://127.0.0.1:3100/api/docs` |

Адреса PostgreSQL и Kafka задаются настройками окружения; это не обязательные адреса Dev/Prod. [Инструкция локального запуска](docs/local-development.md) не требует изменения nginx или конфигурации деплоя.
